## 0. Экспресс-диагностика

Перед поиском сложных причин выполните проверку:
```cmd
scripts\check-ports.bat
```
Скрипт автоматически проверяет:
- Запущен ли процесс `winws.exe` (zapret);
- Активна ли служба DNS Unlocker (`ag_dns.exe`);
- Нет ли "зависших" процессов `language_server.exe`;
- Открыт ли локальный порт `10809`;
- Нет ли активных VPN/WARP/WireGuard интерфейсов;
- Резолвятся ли IP серверов Google AI (`generativelanguage.googleapis.com` и др.).

### «Правило 3 процессов»:
1. 🟢 **zapret** (служба или окно winws с подходящим ALT)
2. 🟢 **Antigravity Unlocker 2** (v2.24.0 / v2.23.1)
3. 🟢 **Antigravity** (запускается ПОСЛЕ запуска первых двух)

## 1. Вечный статус "Working" / Запросы висят по 15–20 минут

### В чем реальная причина?
1. **Включена опция «Прокси из группы» в Unlocker:**  
   Публичный сервер группы Nova перегружен сотнями одновременных запросов («сервера кладут»). Запросы встают в гигантскую очередь или отваливаются по таймауту.
2. **Лимит 128 КиБ на размер запроса и штрафной кулдаун релея (ГЛАВНАЯ ПРИЧИНА):**  
   - **Почему новый чат работает, а старый с историей зависает?**  
     Новый чат весит 2–5 КБ и пробивается моментально. Старый чат с накопленной историей и кодом раздувается **до 130–140 КиБ и более**.
   - **Механизм срыва:** В коде релея пересылкой управляет функция `tls_pump`, которая считывает данные блоками по 16 КБ и сбрасывает их в сокет без троттлинга. При скорости свыше 110–120 КБ/с запрос упирается в стандартный лимит окна потока HTTP/2 (`SETTINGS_INITIAL_WINDOW_SIZE` = 128 КиБ), вызывая `FLOW_CONTROL_ERROR` или аварийный сброс TCP RST.
   - **Штрафной кулдаун:** После 2 обрывов подряд релей **откладывает маршрут на 2 минуты**, а после 7 обрывов — **на 10 минут**! Пока маршрут отложен, клиент крутит статус *Working* до истечения тайм-аута.
3. **Залипание стримингового сокета (Server-Sent Events / SSE):**  
   Ответ модели идет потоком токенов через постоянное HTTP/2 соединение. При микро-сбросе пакета провайдером сокет замирает, а клиент крутит статус *Working*.

### Как это решить:
- ✅ **Шаг 1: Выключите «Прокси из группы»** в Unlocker 2! Запросы должны идти напрямую через zapret.
- ✅ **Шаг 2: Включите «Ротация между серверами: ВКЛ» и «Встроенные выходы: ВКЛ»** в настройках для опытных (это спасает от 10-минутного блэкаута при сбое одного маршрута).
- ✅ **Шаг 3: Не перегружайте один чат выше 128 КБ:**  
  - Не вставляйте огромные куски кода прямо в сообщение — прикрепляйте файлы через `@имя_файла` (IDE считывает их локально, не раздувая JSON запроса).  
  - Используйте команду `/compact` для сжатия диалога.  
  - При старте новой крупной задачи создавайте **новый чат**.
- 💡 **Лайфхак "Раскачки стрима":**  
  Если статус *Working* застрял, отправьте в поле ввода чата любую короткую фразу (например точку `.`, "1" или слово "продолжай") и нажмите Enter. Unlocker мгновенно перезапустит TCP-сокет, и генерация продолжится без потери контекста.

## 2. Ошибка "Model is not available" и сохранение контекста

### Симптом
После первого или второго запроса модель думает и выдает красную плашку `Model is not available`.

### Как лечить БЕЗ потери контекста (не создавая новый чат):
1. **Мягкий реконнект модели:**
   - В правом углу чата переключите активную модель на соседнюю (например, с *Gemini 3.8 Flash* на *Gemini 3.8 Pro* или *Flash Lite*).
   - Отправьте короткий запрос, чтобы контекст подхватился соседним бэкендом.
   - Затем переключитесь обратно на нужную модель.
2. **Перезапуск Antigravity Unlocker 2 "на лету":**
   - Не закрывая саму Antigravity, закройте Unlocker 2 и запустите его снова от имени Администратора.
   - Нажмите в чате Antigravity кнопку **Retry** (Повторить). Контекст останется нетронутым!
3. **Метод "Прогрева сокета" (Тестовый Привет):**
   - Создайте новый чистый чат.
   - Отправьте туда тестовое слово (например «Привет»).
   - Дождитесь ответа модели (это пробивает сокет и верифицирует TLS-сессию).
   - После ответа вернитесь в свой старый рабочий чат с кодом — он продолжит работу без ошибок!

## 3. Недоступна модель Argon и аккаунты (Jio vs Pro)

### В чем причина?
- **Аккаунты Jio Free Trial:**  
  Дешёвые аккаунты "за 200 руб" регистрируются через индийского оператора Jio. Google начал блокировать доступ к флагманской модели Argon и урезать лимиты для таких промо-учеток.
- **Официальный Google One AI Premium ($20/мес):**  
  Модель Argon и максимальные квоты гарантированно работают только на полноценных оплаченных подписках.

## 4. Почему через VPN всё виснет или не работает?

| Характеристика | Обычный VPN | zapret + Antigravity Unlocker 2 |
| :--- | :--- | :--- |
| **Скорость канала** | Режется до 5–15 Мбит/с | Ваша максимальная скорость (до 1 Гбит/с) |
| **Пинг / Latency** | Высокий (европейские серверы) | Минимальный прямой пинг до Google Cloud |
| **Блокировка IP Google** | Высокий риск: IP датацентров VPN в спам-листах | Отсутствует: запросы идут напрямую с вашего IP |
| **Стриминг (SSE)** | Зависает и рвется на больших файлах | Стабильный потоковый прием токенов |

> [!WARNING]
> Если включен VPN, WinDivert (драйвер zapret) физически не может модифицировать сетевые пакеты. **VPN должен быть выключен**.

## 5. Ошибка 400 Bad Request: Моментальная (0.1с) vs С задержкой (3-5с)

### Вариант А: Ошибка вылетает МОМЕНТАЛЬНО (за 0.1 – 1 секунду)
Запрос **не доходит до серверов Google** — его глушит локальный клиент:
1. **Unlocker запущен БЕЗ прав Администратора:**  
   «Автопатч» не может внедрить хуки в исполняемые файлы Antigravity. Запускайте Unlocker строго ПКМ ➔ **Запуск от имени администратора**.
2. **Зараженный токен сессии (грязный кэш):**  
   Если ранее стрим оборвался на 2-3 строках кода, Google записал в файл сессии метку регионального нарушения.  
   **Решение:** запустите `scripts\clear-antigravity-cache.bat` для удаления старых токенов.
3. **Опечатка в прокси:**  
   Убедитесь, что в поле своего прокси указан протокол `https://127.0.0.1:10809` (именно https, а не http).
4. **Проблема USB Wi-Fi свистков ("свистки с Озона"):**  
   Аппаратная разгрузка чексумм чипов Realtek/MediaTek портит пакеты WinDivert.  
   **Решение:** `Win + X` ➔ *Диспетчер устройств* ➔ *Сетевые адаптеры* ➔ Свойства вашего Wi-Fi ➔ вкладка *Дополнительно* ➔ `TCP Checksum Offload` и `UDP Checksum Offload` перевести в **Disabled**.

### Вариант Б: Ошибка вылетает С ЗАДЕРЖКОЙ (через 3 – 5 секунд)
Запрос ушёл в Google, но Google заблокировал регион:
1. В zapret не добавлены домены Google AI. Запустите `scripts\add-to-zapret.bat` и **перезапустите zapret**!
2. Включен «Прокси из группы» — немедленно **ВЫКЛЮЧИТЕ**.

## 7. Ошибки zapret (WinDivert / Не подбирается ALT)

### Код 5 / Код 1753 (`Failed to open WinDivert device`)
1. Завершите старые службы обхода DPI (GoodbyeDPI, GoodCheck, другие копии winws):
   ```cmd
   net stop WinDivert
   sc delete WinDivert
   sc delete WinDivert14
   ```
2. Запускайте `service.bat` **строго от имени Администратора**.
3. Если установлены игры с драйверными античитами (Riot Vanguard, FaceIT) — они могут временно блокировать загрузку `windivert.sys`.

### Домены Google отсутствуют в list-general.txt или служба не перезапущена
В стандартном zapret нет доменов Google AI. Объедините домены через `scripts\add-to-zapret.bat` и **обязательно перезапустите zapret**!

## 8. Ошибки прокси и os error 10061

### Симптом
Сообщение в логе или консоли:  
`Прокси не отвечает: недоступен: Подключение не установлено, т.к. конечный компьютер отверг запрос на подключение. (os error 10061)`

### Причина и решение:
- Ошибка `os error 10061 (WSAECONNREFUSED)` возникает, когда в поле **«Свой HTTP-прокси»** прописан `https://127.0.0.1:10809`, но у вас на компьютере **не запущен** локальный прокси-сервер (Xray, v2ray, Clash, sing-box).
- **Решение:**  
  Если вы не используете собственный локальный туннель, **просто ОЧИСТИТЕ поле «Свой HTTP-прокси» (оставьте его пустым)**!  
  При пустом поле Unlocker будет использовать свои «Встроенные выходы: ВКЛ» напрямую через zapret без ошибок!

## 9. Ошибка в новых чатах: language_server

### Симптом
Пользователь пишет: *«В старых диалогах общение продолжается нормально, а при создании нового чата вылетает: Unknown: Agent execution terminated due to error»*.

### Причина:
В фоновых процессах Windows завис старый процесс **`language_server.exe`** от предыдущей неотпатченной сессии Antigravity. Старые чаты используют кэшированный контекст, а новый чат пытается инициализировать новый сокет через зависший `language_server.exe`.

### Решение:
1. Закройте Antigravity.
2. Запустите скрипт:
   ```cmd
   scripts\clear-antigravity-cache.bat
   ```
   (Скрипт автоматически завершит все зависшие `language_server.exe` и `Antigravity.exe`).
3. Запустите Antigravity заново — новые чаты заработают стабильно.

## 10. Служба обхода не работает (зависший ag_dns)

### Симптом
В окне Unlocker появляется надпись:  
*«Служба обхода не работает. Без неё ошибка 400 не обходится. Кнопка переустановит и запустит её. Жму на кнопку "Починить", и все равно эта ошибка возвращается»*.

### Причина:
Фоновый DNS-демон Unlocker (`ag_dns.exe`) "завис" в памяти и заблокировал сетевой порт/интерфейс. Кнопка «Починить» не может перезапустить его, так как процесс занят.

### Решение в 1 клик:
Запустите от имени Администратора наш скрипт:
```cmd
scripts\fix-unlocker-service.bat
```
Он принудительно снимет зависший `ag_dns`, очистит кэш DNS Windows и разблокирует службу. После этого нажмите в Unlocker кнопку «Починить» — служба запустится мгновенно.

## 11. Черный экран при запуске Antigravity

### Симптом
Пользователь запускает Antigravity (2.0 или IDE), но вместо интерфейса появляется черный экран и окно зависает.

### Причина:
Повреждение кэша аппаратного ускорения Chromium/Electron (`GPUCache`) в папках `%APPDATA%\Antigravity\GPUCache` или `%LOCALAPPDATA%\Programs\Antigravity IDE`.

### Решение:
Запустите `scripts\clear-antigravity-cache.bat` — скрипт автоматически удалит поврежденный `GPUCache`, после чего интерфейс запустится в штатном режиме.

## 12. Ошибка 404 на cloudcode-pa и падение группы

### Симптом
Лог запросов Unlocker показывает:  
`https://daily-cloudcode-pa.googleapis.com/v1internal:loadCodeAssist → 404 Not Found`  
`404=10 через прокси (выходы)`.

### Причина:
Это прямое подтверждение того, что **публичные сервера группы Nova вышли из строя или были заблокированы Google**.  
**Решение:** Отключите «Прокси из группы: ВЫКЛ» и очистите «Свой HTTP-прокси» (оставьте пустым). Трафик пойдет напрямую через zapret на реальные рабочие адреса.

## 13. Проблемы с DNS и утечками провайдера

Провайдеры могут подменять DNS-ответы.
1. В Unlocker 2 включите **«Обход через DNS: ВКЛ»**.
2. В Windows переключите DNS на DoH (Шифрованный DNS):
   - IPv4: `1.1.1.1` (Cloudflare) или `8.8.8.8` (Google).
3. Сбросьте кэш DNS:
   ```cmd
   ipconfig /flushdns
   ```

## 15. Ошибка "Network error" при отправке сообщения

### Симптом
Пользователь пишет сообщение в чат Antigravity (в IDE или 2.0), нажимает Enter, и чат мгновенно выдает красное уведомление:  
`Network error` или `Failed to fetch`.

### Причины и решение:
1. **Брандмауэр Windows (Защитник) заблокировал сетевой доступ:**  
   При первом запуске Antigravity IDE Windows могла выбросить скрытое окно блокировки портов.  
   - Нажмите `Win + R`, введите `control firewall.cpl` и нажмите Enter.  
   - Перейдите в *Разрешение взаимодействия с приложением или компонентом в брандмауэре Защитника Windows*.  
   - Найдите в списке **Antigravity IDE** и **Antigravity** и убедитесь, что стоят галочки напротив **«Частная»** и **«Общественная»**.
2. **zapret запущен БЕЗ прав Администратора:**  
   Если `service.bat` или пресет zapret запущен обычным кликом без прав администратора, драйвер WinDivert не имеет прав перехватывать сокеты. В итоге исходящие запросы к Google уходят в неизмененном виде, провайдер мгновенно рвет TCP-пакет (TCP RST), и интерфейс выбрасывает `Network error`.  
   - Запустите zapret строго через **ПКМ ➔ Запуск от имени администратора**.
3. **Локальный конфликт настроек прокси в самой IDE (VS Code):**  
   Если ранее в системе или в VS Code использовались корпоративные или сторонние прокси:  
   - В Antigravity IDE нажмите `Ctrl + ,` (Настройки), введите `proxy` и убедитесь, что параметр `Http: Proxy` пуст.
4. **Зависли фоновые сетевые службы:**  
   Запустите скрипты `scripts\fix-unlocker-service.bat` и `scripts\clear-antigravity-cache.bat`, после чего перезапустите клиент.

## 16. Особенности настройки на macOS (MacBook / iMac)

Если вы запускаете **Antigravity Unlocker на macOS** (например, `v2.24.0-macos.1`), обязательно обратите внимание на отчёт:

### Разбор частых ошибок в отчёте macOS:
1. **`Права администратора: нет` (Самая главная ошибка):**  
   - В macOS перенаправление DNS-трафика серверов Google выполняется через системный файрвол `pfctl` или `/etc/resolver`.  
   - Без прав суперпользователя служба Unlocker не может прописать правила: в отчете будет написано: `Обход через DNS: частично (правил нет)`.  
   - **Решение:** Запустите Unlocker с подтверждением прав администратора (через ввод пароля macOS / Touch ID), либо запустите бинарник из Терминала через `sudo`.
2. **`Antigravity 2.0: /Applications/Antigravity IDE.app — НЕ пропатчена`:**  
   - В отчёте видно: `Автопатч: выкл`.  
   - **Решение:** Включите переключатель **«Автопатч: ВКЛ»** в Unlocker, чтобы он модифицировал исполняемый файл в `/Applications/`.
3. **`Прокси из группы: вкл, ключ: нет`:**  
   - В отчете видно: `напрямую не отвечает: сервисы разблокировки не подменили адрес — напрямую будет ошибка 400`.  
   - **Решение:** Переведите **«Прокси из группы: ВЫКЛ»** и **«Локальный прокси: ВЫКЛ»**, а **«Встроенные выходы: ВКЛ»**.
4. **zapret на macOS:**  
   - На Mac zapret устанавливается через официальный скрипт `install_easy.sh` (использует демон `tpws` или `nfqws`). Если zapret не установлен, связка Unlocker (со встроенными выходами и правами sudo) работает напрямую.

## 17. Ошибка входа: dial tcp 127.0.0.1:7890 connectex refused

### Симптом
При нажатии «Войти в Google аккаунт» появляется желтый треугольник:  
`There was an unexpected issue setting up your account.`  
`Post "https://oauth2.googleapis.com/token": proxyconnect tcp: dial tcp 127.0.0.1:7890: connectex: No connection could be made because the target machine actively refused it.`

### Причина:
Порт **`7890`** — это порт программы **Clash / Clash Verge / Mihomo**.  
Пользователь закрыл Clash, но в сетевых настройках Windows остался включен «системный прокси» на адрес `127.0.0.1:7890`. Antigravity пытается отправить OAuth2-токен авторизации через закрытый порт, Windows отвергает запрос, и вход падает.

### Решение:
1. Нажмите `Win + I` (Параметры Windows) ➔ **Сеть и Интернет** ➔ **Прокси-сервер**.
2. В блоке *«Настройка прокси вручную»* переведите тумблер **«Использовать прокси-сервер» в положение ОТКЛ**.
3. Проверьте переменные окружения: нажмите `Win + R`, введите `sysdm.cpl` ➔ вкладка *Дополнительно* ➔ *Переменные среды*. Если в списке есть `HTTP_PROXY` или `HTTPS_PROXY` со значением `7890` — удалите их.
4. Вернитесь в Antigravity и нажмите **Continue with different account** — авторизация пройдет мгновенно.

## 18. В одних папках (проектах) работает, а в других нет

### Симптом
Пользователь замечает: *«В одной папке проекта новые чаты работают идеально, а открываю другую папку — там сразу вылетает ошибка или зависает»*.

### Причина:
Antigravity IDE (на ядре VS Code) сохраняет настройки как глобально, так и индивидуально для каждой папки (Workspace) в скрытой подпапке `.vscode/settings.json`.  
Если в старом проекте был прописан локальный прокси (`"http.proxy": "..."`) или закэшировалось битое состояние сокета, этот проект падает, пока остальные папки работают нормально.

### Решение:
1. Откройте проблемную папку проекта.
2. Проверьте, есть ли в ней файл `.vscode/settings.json`. Если там есть строки, содержащие `proxy` — удалите их.
3. Запустите скрипт `scripts\clear-antigravity-cache.bat` и выберите **Режим [1] (Безопасная очистка)** — это сбросит зависший кэш воркспейсов без разлогина.

## 19. Антивирус / Windows Defender пишет, что Unlocker это "троян"

### Симптом
Защитник Windows или сторонний антивирус блокирует `AG_2.24.0.exe` с пометкой *HackTool*, *RiskWare* или *Trojan*.

### Причина:
Это стандартное **ложное срабатывание (False Positive)**.  
Antigravity Unlocker содержит механизм автопатча (внедрение хуков и перехват сетевых вызовов в бинарниках Antigravity) и упакован сжатием исполняемых файлов. Эвристический анализ антивирусов часто вешает флаг "HackTool/Trojan" на любые легитимные патчеры софта.

### Решение:
1. Откройте: *Параметры Windows ➔ Конфиденциальность и безопасность ➔ Безопасность Windows ➔ Защита от вирусов и угроз*.
2. В разделе *Параметры защиты от вирусов и других угроз* нажмите **Управление настройками**.
3. Пролистайте вниз до пункта **Исключения** ➔ *Добавление или удаление исключений*.
4. Нажмите *Добавить исключение ➔ Папка* и выберите папку, где лежит `AG_2.24.0.exe`.

## 20. Linux: "Служба обхода не запустилась: не удалось запустить systemd-юнит (systemctl --user)"

### Симптом
На Linux в Antigravity Unlocker горит красный индикатор:  
*«Служба обхода не работает. Без неё ошибка 400 не обходится»*.  
В журнале внизу:  
`Служба обхода не запустилась: не удалось запустить systemd-юнит (systemctl --user)`

### Причина
1. **Сломан или отсутствует пользовательский bus systemd (`systemctl --user`):**  
   Это типично для WSL, Docker-контейнеров, входа через `su`/`sudo`, сессий без PAM (`$XDG_RUNTIME_DIR` / `$DBUS_SESSION_BUS_ADDRESS` не установлены) или дистрибутивов без systemd (Alpine, Void, Artix, Devuan). В такой среде `systemctl --user` не может связаться с менеджером служб.
2. **Опечатка в адресе локального прокси:**  
   На скриншоте в поле *«Свой HTTP-прокси»* часто встречается опечатка: `http://ocalhost:10808` (пропущена буква `l` в начале `localhost`).

### Решение 1. Как найти и запустить службу вручную в терминале:

1. **Где лежит юнит:**  
   Пользовательские юниты systemd на Linux хранятся в:
   ```bash
   ls -la ~/.config/systemd/user/
   ```
   Посмотрите содержимое юнит-файла (обычно `ag_dns.service`):
   ```bash
   cat ~/.config/systemd/user/ag_dns.service
   ```
   В строке `ExecStart=` будет указан точный абсолютный путь к исполняемому файлу службы (обычно `~/.local/share/AGUnlocker/ag_dns` или `~/.config/AGUnlocker/ag_dns`).

2. **Запуск напрямую без systemd:**  
   Сделайте бинарник исполняемым и запустите его напрямую в терминале:
   ```bash
   chmod +x ~/.local/share/AGUnlocker/ag_dns
   ~/.local/share/AGUnlocker/ag_dns &
   ```
   Либо найдите файл поиском по системе:
   ```bash
   find ~ -name "ag_dns" -type f 2>/dev/null
   ```

3. **Если systemd есть, но сбоит:**
   Проверьте статус и точный текст ошибки:
   ```bash
   systemctl --user status ag_dns
   journalctl --user -xe -u ag_dns
   ```
   Перезагрузите конфигурацию и запустите заново:
   ```bash
   systemctl --user daemon-reload
   systemctl --user restart ag_dns
   ```

### Решение 2. Использование открытого NovaAntigravity Relay (AG-Relay)
Чтобы вообще не зависеть от systemd, служб и закрытых бинарников на Linux:
1. Скачайте папку `relay/` из этого репозитория.
2. Запустите релей:
   ```bash
   python3 relay/relay.py
   ```
3. Запустите Antigravity с проброшенным портом:
   ```bash
   export AG_LS_PROXY=http://127.0.0.1:10809
   antigravity &
   ```
